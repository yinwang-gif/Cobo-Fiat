PRODUCT DESIGN · COBO FIAT
Cobo Fiat 法币操作中枢
以法币操作为核心的资金工作台。客户在 Cobo 体系内持有的稳定币与法币余额，可以统一管理、按需转化，并通过两条独立路径完成提现与下发。本方案说明产品定位、资金来源、余额模型与出口逻辑，后续「交互原型」是这套思路的可视化呈现。
01 / 产品定位
Cobo Fiat 是什么
不是一个换汇工具，而是一个带稳定币入口的法币账户与结算工作台。
Cobo 已经具备数字货币侧的基础——Portal、托管钱包、稳定币收单、Off-ramp Core 都已跑通。Cobo Fiat 要补齐的是法币侧的操作能力：让客户不仅能把稳定币换成法币，更能像使用一个真正的法币账户一样，收款、持有、提现、下发。
已具备
数字货币侧
Portal + 托管钱包 + 稳定币收单 + Off-ramp Core。客户的稳定币持仓与收单能力已经成熟。
本方案
法币侧
VA 法币账户 + 余额池 + 提现 + 下发。对标 Airwallex / Wise Business，但多了稳定币入口。
客户粘性的来源不是某一次的汇率价格，而是从收款到结算整条链都在 Cobo 内——VA 账户、余额、合规、路由、对账都在一处，迁移成本很高。
02 / 账户模型
两层账户：组织持有资金，商户标记归属
客户既有自营企业，也有服务大量底层商户的平台型客户（PSP、OTC、电商）。账户分两层，且商户层是可选的。
组织层 · Organization
客户的法律主体，真正持有资金、发起操作的层
  • 持有 VA 法币账户、法币余额池、组织同名银行账户
  • 是合规主体，承担组织级 KYB
  • 提现、下发都由组织层发起
商户层 · Merchant（可选）
组织底下的归属单元，不是独立法律主体
  • 拥有商户级收款地址、商户子账本、商户专属的收款方
  • 资金物理上归集到组织层，但每一笔都带商户标记
  • 有自己的商户 KYB；由组织收集申报、对真实性负责，Cobo 抽查
核心原则
钱在组织层，归属在商户层。资金统一在组织层管理，但来源、归属、去向都打上商户标记——这是「全链路可追踪」的基础。
🔀
商户层可选：有底层商户的平台客户可以按商户细分；自营企业可以不建商户，所有操作默认归到组织自身。不强制两层，避免伤害无商户的客户。
03 / 实体建模
三个独立实体：商户、收款方、关联
把「归属」「去向」「连接」拆成三个独立对象，而不是揉在一起——这是同时容纳所有复杂情况的关键。
◑
商户 Merchant
这笔钱属于谁
组织底下的归属单元。有自己的 KYB、子账本、收款地址。
◎
收款方 Beneficiary
这笔钱打给谁
一个银行账户 + 持有人信息。有自己的验证状态，是下发目标。
⇄
关联 Link
谁能打给谁
不是字段，是一层关系。一个商户可关联多个收款方；收款方可被多商户复用。
把「关联」单独拎出来，模型就能同时容纳两种情况：商户 ≠ 收款方（商户把款下发给它的供应商）和商户 = 收款方（组织代收商户的款、再下发还给商户自己——只需把商户的银行账户登记成一个收款方、关联回它自己）。
💡
为什么不把收款方做成商户的子字段：复用（同一收款方可被多商户共用，避免重复录入与 KYB）、自洽（商户作为自己的收款方不会变成自我引用）、兼容无商户客户（收款方可直接挂在组织层）。
04 / KYB 与材料
两层 KYB 的责任划分
Cobo 直接审组织；商户的 KYB 由组织收集申报、组织对真实性负责，Cobo 抽查复核。
层级KYB 对象材料内容提交方审核方
组织级 KYB 客户组织本身 营业执照、注册信息、UBO、董事、银行信息 客户组织 Cobo 直接审核
商户级 KYB 组织底下每个商户 商户营业执照、注册信息、UBO、业务说明、与组织关系证明 组织代为申报 组织初审 + Cobo 抽查
🔗
KYB 复用：当商户把自己的银行账户登记成收款方时，这个收款方的验证直接复用商户 KYB 结果——同一主体不做两遍。
05 / 资金守恒
组织层与商户层的账务关系
组织层持有全部资金，商户子账本是其中「已归属」的部分。两者不必相等，但永远不能倒挂。
组织层余额池  =  Σ(各商户子账本)  +  组织未分配 / 自有资金
差额（组织未分配 / 自有）来自三类：组织自有资金（principal 库存、运营资金、对冲头寸、prefunding）、未归属入金（尚未打商户标记或待分配）、组织级业务余额（如 On-ramp LP 自有业务收款）。
硬约束 · 资金安全底线
Σ(商户子账本)  ≤  组织层实际余额   ——  任何时刻必须成立
一旦各商户子账本之和超过组织实际余额，意味着账面记着商户有钱、但组织实际不足——这是穿仓 / 资金缺口，属于严重对账事故。这条约束须由中后台运营系统实时校验，任何越界立即告警。

07 / 余额模型
统一余额池，但来源有「记忆」
客户看到的是一个统一余额；系统内部为每一笔资金保留来源标记，路由层在下发时据此校验。
余额池表面是一个数字，但下发给第三方时，不是所有资金都能无差别使用。来源属性决定了它的合规可用性——这一层逻辑客户无需感知，只在下发被拦截时才会以提示形式浮现。

两个独立出口：提现 vs 下发
